# 第 3 章 国产软件技术基础

考核占比 20%。重点考察国产基础软件的基本概念、功能分类及通用工作原理。

## 3.1 数据库基础

### 关系数据库

关系数据库用表组织数据，表由行和列构成。

- 主键唯一标识表中的记录
- 外键等关联字段用于建立表之间的关系
- 订单表通过 customer_id 关联客户表，体现表与表之间的关联关系
- DBMS 提供数据定义、查询、事务等管理能力
- 基本 SQL 操作：SELECT 查询、INSERT 插入、UPDATE 更新、DELETE 删除

### 事务与 ACID

事务是一组不可分割的操作序列。

- 原子性要求事务中的操作要么全部成功，要么作为整体失败
- 一致性保证事务执行前后数据都处于合法状态
- 隔离性保证并发事务互不干扰
- 持久性保证提交后数据不会丢失
- 事务隔离级别包括读未提交、读已提交、可重复读、串行化，隔离级别越高并发性能越低

### 索引

- 索引提升特定查询的速度
- 索引需要额外存储空间
- 索引会增加写入和维护的成本
- 建立索引只会加快读取而增加写入维护成本

### NoSQL 数据库

NoSQL 按数据模型分为多种类型：

| 类型 | 数据组织 | 适合场景 |
|---|---|---|
| 键值 | 键值对 | 按唯一键快速读写简单状态 |
| 文档 | JSON 文档 | 灵活结构、嵌套数据 |
| 宽列族 | 列族组织 | 海量稀疏数据 |
| 图 | 节点与边 | 关系网络查询 |

- 键值模型适合按唯一键快速读写大量简单状态，例如会话状态
- 宽列模型适合海量稀疏、按列族组织的数据
- NoSQL 按数据模型分类，与存储介质无关

### 数据库迁移

- 数据库迁移不能只比较数据条数
- 需要检查结构、SQL 兼容、数据一致性和关键业务功能
- 必要时评估性能与高可用方案

## 3.2 中间件

### 中间件的定位与能力

中间件位于操作系统基础能力与业务应用之间，为分布式应用提供通用能力。

- 通用能力包括事务协调、通信、消息传递、服务治理
- 中间件减少应用重复实现，促进系统集成
- 企业把认证、消息事务等通用能力集中到中间件层，避免每个应用各自实现

### 消息队列

消息队列通过生产者、队列或主题、消费者实现异步与解耦。

- 生产者发送消息，消费者按自身能力处理
- 高峰期请求短时间激增时，消息队列先承接再按消费者能力处理，实现削峰缓冲
- 异步处理让生产和消费解耦，不互相阻塞

消息可靠处理需要以下机制配合：

- 确认机制，消费者处理成功后才确认，避免失败被当作成功
- 失败重试，处理失败的消息重新投递
- 幂等处理，重复消费同一消息不会产生重复业务
- 死信或异常消息处理，超过重试次数的消息转入专门队列

### 常见中间件

- 消息中间件：Kafka 面向高吞吐日志和流处理，RabbitMQ 面向灵活路由和低延迟
- 缓存中间件：Redis 内存键值存储，用于缓存和会话
- 分布式协调：ZooKeeper 等提供配置与协调能力

## 3.3 兼容与迁移验证

### 业务栈兼容验证

- 完整业务栈包括操作系统、数据库、中间件和应用
- 兼容验证应针对实际组合后的完整技术栈和相关业务路径
- 只验证某个单品能否启动不足以证明整套系统兼容
- 应用能启动并不能认定各组件之间不存在兼容性问题

### 应用迁移流程

1. 盘点应用清单与依赖，识别迁移范围、依赖和潜在问题
2. 完成目标架构搭建
3. 功能验证
4. 兼容性验证
5. 回归测试

- 回归测试用于确认迁移没有破坏既有相关功能
- 新系统上线前执行回归测试是标准环节
- 跨架构迁移涉及编译、运行库和驱动等层面的兼容性检查

### 分布式系统概念

- CAP 定理表明分布式系统在一致性、可用性、分区容错性之间需要取舍
- 分区容错性在分布式系统中必须满足
- 单点故障风险通过冗余和集群方案降低
- 容器化用 Docker 等工具打包应用与环境，实现环境一致性

## 3.4 国产基础软件生态

信创环境下国产软件覆盖基础软件各层：

- 国产数据库：达梦数据库、人大金仓、GaussDB、openGauss、OceanBase
- 国产中间件：东方通中间件、金蝶天燕、宝兰德
- 国产办公软件：金山 WPS、永中 Office
- 国产操作系统：统信 UOS、麒麟系统
- 国产浏览器：360 安全浏览器等基于 Chromium 内核的国产浏览器

- 国产软件与 X86、ARM 等多种架构适配
- 国产数据库大多兼容主流 SQL 标准，支持事务和索引等基础能力
- 中间件提供消息、事务、服务治理等通用能力，应用通过标准接口接入
- 信创环境强调软硬件全栈自主可控，从芯片、操作系统到应用软件形成完整生态

## 3.5 虚拟化与容器

### 虚拟机与容器

- 虚拟机通过 Hypervisor 模拟完整硬件，每个虚拟机包含独立操作系统，隔离性强、开销大
- 容器共享宿主机内核，只打包应用及依赖，启动快、资源占用小
- 容器适合微服务和批量部署，虚拟机适合强隔离场景
- Docker 是主流容器工具，镜像包含应用和运行环境，镜像构建后可在任意 Docker 环境运行

### 容器基础命令

- docker pull 拉取镜像，docker run 运行容器，docker ps 查看运行中容器
- docker build 从 Dockerfile 构建镜像
- docker stop 停止容器，docker rm 删除容器
- 容器网络和存储卷提供对外访问与数据持久化

## 3.6 数据文件与 JSON

- JSON 是轻量级数据交换格式，以键值对和嵌套结构组织数据
- JSON 适合保存结构化数据，例如学生信息、配置项
- 程序启动时从数据文件加载数据，写入时保存到文件，实现持久化
- 数据持久化保证程序重启后数据不丢失
- 数据处理流程：读取文件、解析、更新、写回文件
- 统计类结果从数据实时计算得出，写死在程序中的固定结果无法反映数据变化

### 容器与智能体环境

- 智能体运行环境可用容器打包，保证依赖一致
- 模型推理服务常以容器方式部署，便于迁移和扩缩容
- 容器环境与宿主机隔离，访问宿主机资源需要显式挂载和权限配置
