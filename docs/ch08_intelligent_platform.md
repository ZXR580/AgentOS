# 第 8 章 智能平台（UOS AI 智能办公生态）

> **本章主线：用"搭建一座智能平台"的顺序，把 5 张图串成一个体系。**
>
> 一个智能平台不是功能堆砌，而是**分层长出来的**。它由四层构成，彼此是承接关系：
>
> | 层 | 回答什么 | 承载章节 |
> |---|---|---|
> | **底座** 顶起全局的骨架 | 智能体能力如何被平台化组织 | 8.5 Agent OS 分层架构 |
> | **血肉** 接入海量外部能力 | 应用/技能/AI 能力如何进来 | 8.3 智能生态（MCP / Skills / SDK） |
> | **功能** 长成用户可用的能力 | 进来的能力如何变成"能写、能办" | 8.1 智能写作、8.2 智能办公 |
> | **触达** 把能力送达到人手中 | 能力如何在跨端场景被调用 | 8.4 智能协同 Uclaw |
>
> 四层的关系一句话：**底座（Agent OS）决定"能力在哪儿被组织"，生态（MCP/Skills/SDK）决定"能力从哪儿来"，功能（写作/办公）决定"能力被用来干什么"，触达（Uclaw）决定"人在哪里用"。**
>
> 全章重点回答"**是如何实现的、如何构建的**"，并联动第 2 章 UOS 系统能力、第 3 章系统软件、第 4 章智能体技术、第 7 章 MCP 实践。
>
> 来源：统信软件智能平台产品方案（2026 第三届教育信息技术应用创新大赛），是国产操作系统 AI+ 生态的落地形态。

## 8.1 智能写作

> 本节解决：AI 写文章如何做到"内容可信、每句有据、数据不出门"。
>
> **层定位**：功能层——能力长出来后最基本的落地形态（"写"这件事）。

- **定位**：基于本地素材权威成文，确保内容真实可信可溯
- **一键投喂**：基于本地素材与大纲成文，每一句话都踩在需求点上——不是凭空生成，而是先把本地资料"喂"给模型，再按照大纲逐段成文
- **在线修改**：集成编辑器，可对大纲、正文在线"整容"（调整结构、改写语句），写、改一个界面完成
- **安全可控**：支持本地 / 私有模型生成，数据"不出门"——素材与生成内容不离开本机或私有环境
- **有据可查**：生成内容标注参考来源，专业且严谨——每段可追溯来自哪份素材

**如何实现 / 构建**：

- 关键是"本地素材前置到模型之前"：先做文档导入与解析，把素材切段、用 Embedding 转成向量（RAG 检索增强，联动 ch04 §4.10）；成文时按大纲逐段检索相关素材并引用
- 用本地 / 私有化模型推理（数据不出域，联动 ch04 §4.18 推理服务），实现"安全可控"
- 生成时对每个关键句挂"来源引用"，实现"有据可查"
- 一句话总结：**素材进 → 检索定位 → 按大纲成文 → 标注来源 → 本地模型生成**，五步闭环。

- 衔接：写作是"单点"能力；跨出文档去调用别的应用时，需要"任务拆解 + 工具协同"——下一节讲智能办公。

## 8.2 智能办公

> 本节解决：怎样让一句自然语言，自动拆解成一串操作、由多个应用协同完成。
>
> **层定位**：功能层（进阶）——从"写"扩大到"办"，跨出文档、调用全局。

- **定位**：一句话完成跨应用、跨业务系统的复杂任务
- **智能的任务拆解**：UOS AI 具备强大的任务理解与拆解能力，能把用户意图自动分解为多个执行步骤，并协调系统工具与应用协同完成任务——让工作从"多步操作"升级为"一句话完成"
- **全面的技能体系**：支持 MCP 与 Skills 技能调用机制，可根据任务目标智能组合或自动生成新技能，持续扩展能力边界，满足多样化办公需求
- **广泛的业务场景**：一键下载视频、一键合并 PDF、一键总结邮件……

**如何实现 / 构建**：

- 核心是"**意图 → 目标 → 步骤**"的规划与工具协同闭环：用户一句话 → LLM 解析意图 → 拆成多个可执行子步骤（Planning，联动 ch04 §4.4）→ 每步调用对应工具 / 应用（Function Calling / MCP，联动 ch04 §4.5 / 4.6）→ 汇总结果返回
- 能力扩展靠两套机制：**MCP**（接入第三方应用，解决"怎么接"）+ **Skills**（把高层任务封装成可复用好用的能力，联动 ch04 §4.7，解决"怎么用"）
- "一键合并 PDF"这类预置场景 = 已把多个子步骤封装成可复用 Skill，用户只需一句话触发
- 一句话总结：**会拆解（规划）+ 能调用（工具/MCP）+ 好复用（Skills 沉淀）**，共同撑起"一句话办成一件事"。

- 衔接：要支撑这么多应用与技能的接入，底层需要丰富的外部生态——下一节讲智能生态（MCP / Skills / SDK）。

## 8.3 智能生态（MCP / Skills / SDK）

> 本节解决：智能平台靠什么把海量应用、技能、AI 能力"灵活接入"，打造企业专属智能助手。
>
> **层定位**：血肉层——决定"能力从哪儿来"，是平台与外部世界的接口。

- **定位**：灵活接入生态能力，打造企业专属智能助手。三大抓手：**MCP（连通）、Skills（技能）、SDK（构建）**。

**MCP：连接更广泛**——三方应用无缝接入，一键联动常用办公系统

- 规模：word、excel、图表分析、12306 等 **9000+** MCP
- 机制：MCP 统一工具接口标准，Server 提供 Tool，Client（UOS AI）负责连接与调用（联动 ch04 §4.6 与第 7 章实践）

**Skills：技能更全面**——自动拆解任务，1.2W+ 技能智能调用 / 自建

- 规模：**1.2W+** 常用 skills
- 机制：Skill 是封装好的高层任务能力，抽象层级高于单个底层 Tool；可按任务自动组合，也能自建（联动 ch04 §4.7）

**SDK：AI 应用构建更简单**——客户可灵活调用快速集成，基于现有系统快速构建 AI 应用

- 规模：**60+** AI SDK，覆盖语音转文字、图像识别等
- 机制：把通用 AI 能力（语音、视觉、文本、知识库、模型管理）封装成 SDK 接口，开发者在现有系统里快速集成，不必从零搭建（对应 Agent OS 的 AI SDK 层）

**如何构建**：

- 生态构建是"**三层递进**"：先定标准（MCP 统一工具接口）→ 再沉淀能力（Skills 把反复用到的任务封装）→ 再提供开发入口（SDK 让客户二次开发）
- 三者关系：**MCP 解决"怎么接"，Skills 解决"接进来怎么用得更顺"，SDK 解决"别人怎么基于它再开发"**
- 规模背后的复用逻辑：9000+ MCP、1.2W+ Skill、60+ SDK，靠的是"标准统一 + 生态开放"——只要按标准注册，任何应用、技能、AI 能力都能被 UOS AI 调用。

- 衔接：能力丰富之后，还要解决"人在哪里用、多端怎么同步、安全怎么控"——下一节讲智能协同 Uclaw。

## 8.4 智能协同 Uclaw

> 本节解决：手机与电脑如何跨端协同，远程操控与安全如何兼得。
>
> **层定位**：触达层——决定"人在哪里用"，把能力跨端送达到用户。

- **定位**：跨端无界，一屏掌控手机与电脑
- **开箱即用**：符合国内用户使用习惯，深度打通飞书、钉钉、QQ 等主流应用接口，一键部署即刻使用
- **手机跨端操控**：通过手机发送指令，AI 自动执行复杂操作，随时随地远程掌控系统
- **高效节能**：深度融合系统能力，通过"工具直达执行路径"，避免冗余推理，大幅降低计算消耗
- **安全可控**：基于 USEC 安全体系，实现权限精细化管控，确保系统稳定与用户数据安全

**如何实现 / 构建**：

- 跨端协同靠"**同一套 AI 能力 + 端侧 / 云侧指令通道**"：手机发指令 → 端侧智能体理解 → 直接调用系统工具执行；不绕大模型做无谓推理，正是"工具直达执行路径，避免冗余推理、降低计算消耗"
- "深度打通飞书 / 钉钉 / QQ"= 这些应用以 MCP / Skill 方式接入，一键部署即注册好连接（对应 8.3 生态）
- 安全靠 USEC 体系：权限精细化管控 + 数据不出域（联动 ch02 权限、ch04 §4.15 安全），与"智能写作数据不出门"一脉相承
- 一句话总结：**端侧智能体 + 免冗余直达 + 权限管控**，实现"手机一句话、电脑自动办"。

- 衔接：以上所有能力最终需要一个完整的平台来承载、调度——下一节看 Agent OS 如何分层把它们组织起来。

## 8.5 Agent OS 平台架构

> 本节解决：UOS AI 的智能能力如何被分层组织成可扩展的平台，每一层做什么、彼此如何协作。
>
> **层定位**：底座层——顶起整个平台的骨架，其余三层的"承重墙"。

- **定位**：**Agent OS**，是 UOS AI 把"智能体能力"系统化、平台化的分层架构。自下而上五层：**模型调度层 → 系统能力层 → AI SDK → 智能体服务层 → 应用能力层**。

**模型调度层**：统一多种模型接入与路由

- 统一运行时：llama.cpp / ONNXRuntime / OpenVINO——把不同推理引擎抽象成统一运行时（联动 ch04 §4.18）
- 统一 API 网关：DeepSeek / Kimi / GLM / QWen、GPT / Claude / 自定义接口——对外统一接口，屏蔽各模型差异
- 混合路由引擎：端侧模型 / 云侧模型 / 私有化部署模型，按场景自动选择

**系统能力层**：把系统级能力沉淀为通用服务

- 系统业务管理：RAG 服务、文本服务、语音服务、图像服务
- 模型任务管理：任务队列、会话管理
- 系统调度管理：模型路由、模型配置

**AI SDK**：面向开发者提供通用 AI 能力接口

- 语音接口、视觉接口、文本接口、知识库接口、模型管理接口——对应智能生态"60+ AI SDK"的规范化形态

**智能体服务层**：让智能体"能感知、能安全运行、有记忆"

- 全局场景感知：语义感知 / 屏幕感知 / 语音感知、用户交互感知 / 系统事件感知 / 外设网络设备感知
- 运行沙箱环境：智能体行为识别、运行时沙箱（安全隔离，联动 ch04 §4.15）
- 记忆与个性化：分层记忆 / 记忆管理、用户画像 / 个性化交互（联动 ch04 §4.9）

**应用能力层**：面向用户的具体能力

- 通用智能体能力：智能体管理 / 推理核心 / 智能体编排与路由
- 办公与生产力：UOS AI 通用智能体、写作智能体、数据分析（对应 8.1 / 8.2）
- 伴随式 AI 助手：7×24 待命 / 记忆系统、友好交互 / 强大的能力
- 三方扩展：智能体插件 / MCP / Skills（对应 8.3 生态接入）

**如何构建 / 组织**：

- 分层原则：**下层提供通用能力，上层组合成业务能力**——模型调度层屏蔽"跑什么模型"，系统能力层把 RAG / 文本 / 语音做成通用服务，AI SDK 给开发者统一入口，智能体服务层赋予"感知 + 安全 + 记忆"，应用能力层才面向用户
- 横向贯穿条：**AI SDK** 是横切层，给各层与外部提供一体化接口
- 分层价值：接入新模型、新增应用、扩展技能都不必改动上层——**生态可插拔、能力可演进**
- 一句话总结：**五层分工 + AI SDK 横切**，把分散的智能体能力组织成一个可持续扩展的操作系统级平台。

> **全章串联：一座智能平台是"长"出来的，不是"堆"出来的。**
>
> **构建链路（自下而上）**：
> 1. 先立**底座**——Agent OS 把智能体能力分五层组织（8.5），决定"能力在哪儿被组织"；
> 2. 再通**血肉**——用 MCP / Skills / SDK 接进海量外部应用、技能与 AI 能力（8.3），决定"能力从哪儿来"；
> 3. 后长**功能**——把这些能力打包成"能写、能办"的用户应用（8.1 写作、8.2 办公），决定"能力用来干什么"；
> 4. 终达**用户**——靠 Uclaw 跨端触达（8.4），决定"人在哪里用"。
