# 第 2 章 国产操作系统技术基础

考核占比 20%。以统信 UOS 为主，UOS 基于 Linux 内核开发，面向国产 CPU 平台。

> **本章主线**：先明白"系统是什么、如何启动"（内核与启动流程），再掌握"如何操作系统"（Shell 与命令），随后深入四类资源管理（文件权限、进程服务、存储、网络），最后落到"如何装软件与生态适配"和"实操命令闭环"。

## 2.1 系统架构与内核

> 本节解决：UOS 到底是什么，内核承担什么职责，硬件事件如何进入操作系统。

### Linux 与 UOS

- UOS 是统信软件基于 Linux 内核开发的国产操作系统
- Linux 系统由内核、用户空间、系统服务、Shell 及图形环境组成
- 内核是系统的核心，负责管理全部资源（详见下方"内核"小节）
- Shell 是命令行解释器，接受用户命令并调用系统程序（详见 2.3）

### 内核

- **内核是操作系统的核心程序**：运行在 CPU 特权模式（内核态），是唯一能直接操作硬件的软件
- **管什么**（对应本章四类资源）：进程（调度与切换）、内存（分配回收与 swap）、文件（文件系统与 inode）、设备（驱动与中断）、权限（用户/组与访问控制）
- **为什么应用必须经内核访问硬件**：应用运行在受限的用户态，读写磁盘、网卡、分配内存都要通过系统调用请内核代办
- 两个理由：
  - 安全隔离：单个程序崩溃或越权不会拖垮整个系统
  - 统一抽象：不同厂商的硬件被抽象成统一接口，应用无需关心底层型号
- **系统调用是用户程序进入内核的入口**：硬件事件处理和用户程序运行都经由内核机制完成
- **Linux 是单体内核**：进程、内存、文件系统、驱动等核心能力都在同一内核空间内
- 与国产化的关系：UOS 基于 Linux 内核，内核是对国产 CPU 架构适配的关键层（联动 2.9 生态适配与第 5 章硬件）

### 中断机制

- **解决什么问题**：若没有中断，CPU 必须不断"轮询"设备状态，既浪费算力又难以及时响应；中断让设备主动"通知"处理器
- 硬件设备通过中断通知处理器，系统发生硬件中断后，处理器暂停当前执行流，转到相应的中断处理路径，中断处理完成后返回被中断的程序继续执行
- 中断类型：硬件中断（设备发起）、异常、系统调用（程序发起）
- 区分：**系统调用**（用户程序主动请求内核服务，向下）、**中断**（硬件设备通知处理器，异步）、**信号**（内核向进程通知事件，进程级，详见 2.6）
- 衔接：内核是资源管理者，中断是硬件与内核的交互通道；下一节展示内核如何被加载并接管整个系统——启动流程。

## 2.2 Linux 启动流程

> 本节解决：开机后系统如何一步步"活"起来，故障时去哪里看日志。

### 启动四阶段

- 开机流程是一条接力链：**固件初始化硬件 → GRUB 引导程序加载内核 → 内核初始化硬件并挂载根文件系统 → systemd 以一号进程身份启动系统服务**
- 为什么 systemd 是一号进程（PID 1）：内核启动完自身后需要第一个用户态进程来拉起其余服务，systemd 接管后成为所有服务的祖先
- systemd 管理服务的启动依赖顺序，保证服务按序拉起
- 图形界面和命令行登录分别进入不同的目标级别
- 为什么设计成阶段式：每一阶段只依赖前一阶段已完成的最小能力——硬件初始化不依赖文件系统、服务启动不依赖内核细节，降低耦合、便于定位故障

### 启动排障

- 启动过程可查看内核日志，故障定位用 dmesg 或 journalctl
- 判断故障阶段：固件/GRUB 阶段看引导配置，内核阶段看 dmesg，服务阶段看 journalctl
- 衔接：启动完成后系统就绪，用户通过 Shell 与系统交互——下一节讲 Shell 与命令基础。

## 2.3 Shell 与命令基础

> 本节解决：如何通过命令行与操作系统交互，命令怎么写、如何组合、如何脚本化。

### Shell 的作用

- Shell 是用户与内核之间的命令行解释器，接收命令并调用系统程序执行
- 终端是 Shell 的运行载体，常见 Shell 有 bash、zsh
- UOS 默认使用 bash，脚本文件以 .sh 结尾
- 为什么先学 Shell：后续所有章节的命令（chmod、ps、systemctl、df、ip 等）都通过 Shell 输入，Shell 是操作系统的"操作台"

### 命令结构

- 命令基本形式为命令名加参数和选项，例如 ls -l /etc
- 选项以单个短横线或双短横线开头，例如 -a、--all
- 多个命令用分号顺序执行，管道符 | 把前一个命令的输出传给后一个命令
- 重定向符号 > 把输出写入文件，>> 追加写入，< 从文件读取输入
- 通配符 * 匹配任意字符，? 匹配单个字符
- 为什么管道强大：单个命令只做一件事，通过管道把"数据流"串联，形成"小而专、可组合"的设计哲学，这是 Linux 命令生态的核心

### 命令组合写法

```bash
# 分号：顺序执行多条命令
cd /tmp; ls; echo done

# 管道：前命令输出作为后命令输入
ps aux | grep nginx

# 重定向：覆盖写 / 追加写 / 从文件读
echo hello > out.txt      # 覆盖写入
echo world >> out.txt     # 追加
sort < in.txt             # 从文件读入

# 通配符：* 任意字符，? 单个字符
ls *.txt                  # 匹配所有 .txt
ls file?.log              # file1.log、fileA.log

# 后台与持久运行：& 放后台，nohup 关终端后继续
sleep 100 &
nohup ./app.sh > app.log 2>&1 &
```

### 常用组合用法

- ps aux | grep nginx 查找特定进程
- df -h 以易读格式查看磁盘空间
- du -sh /var 查看目录总占用
- journalctl -u 服务名 查看指定服务日志
- tail -f 日志文件 实时跟踪日志输出
- history 查看命令历史，Ctrl+C 中断当前命令

### 环境与变量

- PATH 环境变量决定命令的查找路径：输入命令名时 Shell 按 PATH 列出的目录逐个查找可执行文件，找不到则报 command not found
- echo 输出内容，$ 符号引用变量值
- 环境变量对子进程继承，脚本中可用 export 导出变量

具体写法：

```bash
name="uos"                # 变量赋值，= 两侧不能有空格
echo $name                # 引用变量，输出 uos
echo "my os is $name"     # 双引号内会展开变量
export name               # 导出给子进程
echo $PATH                # 查看命令查找路径
which bash                # 定位命令所在路径
```

### 脚本基础

- 脚本首行写 #!/bin/bash 指定解释器
- 变量赋值无空格，引用时加 $ 符号
- if 条件判断、for 循环、while 循环是常用流程控制
- 脚本赋予执行权限后用 ./脚本名 运行
- 定时任务 crontab 可周期性调用脚本
- 为什么首行要写 #!/bin/bash：它告诉内核用哪个解释器执行该文件，不写则按当前 Shell 的默认方式解析，行为容易不一致

脚本骨架示例：

```bash
#!/bin/bash
# 变量：赋值无空格，引用加 $
dir="/var/log"
# if 条件判断
if [ -d "$dir" ]; then
  echo "$dir 存在"
else
  echo "$dir 不存在"
fi
# for 循环：遍历匹配文件
for f in /etc/*.conf; do
  echo "配置文件: $f"
done
# while 循环：计数
i=1
while [ $i -le 3 ]; do
  echo "第 $i 次"
  i=$((i+1))
done
```

```bash
# 赋执行权限后运行
chmod +x myscript.sh
./myscript.sh
# 或用 bash 直接解释执行（无需执行位）
bash myscript.sh
```

### 终端操作考点

- 查看命令帮助用 man 命令名
- which 命令名 查看命令所在路径
- sudo 以管理员权限执行命令
- 用户切换用 su，退出登录用 exit
- Ctrl+Z 挂起前台任务，jobs 查看任务列表，fg 恢复前台运行
- nohup 命令让进程在终端关闭后继续运行，配合 & 后台执行
- 衔接：命令大量围绕"文件与目录"展开——下一节讲目录与文件操作命令。

## 2.4 目录与文件操作

| 命令 | 用途 |
|---|---|
| mkdir | 创建目录，-p 可一次创建多层目录 |

## 2.5 文件系统与权限

> 本节解决：文件在磁盘上如何存储、权限如何控制、为何默认权限是 644/755。

### 文件系统

- 常见文件系统类型有 ext4、xfs、btrfs，UOS 默认使用 ext4
- 目录结构遵循 FHS：/etc 存配置、/var 存日志与可变数据、/home 存用户数据、/tmp 存临时文件、/opt 存第三方软件
- 文件系统用 inode （索引节点）记录文件的元数据（大小、属主、权限、数据块位置等），文件名只是指向 inode 的目录项
- 硬链接共享同一 inode，删除任一链接不影响其他链接；软链接是指向路径的特殊文件，目标被删则失效
- 为什么区分硬/软链接：硬链接不能跨文件系统、不能指向目录，软链接没有这些限制；排障中"软链接失效"常见于目标被移动或删除

### 权限模型

- 权限分读 r、写 w、执行 x 三种
- 访问者分所有者、所属组、其他用户三类
- 权限用符号或数字表示，例如 755 对应 rwxr-xr-x
- 数字权限中 4 表示读、2 表示写、1 表示执行，相加得到权限值
- 644 表示所有者可读写、组和其他用户只可读，是普通文件的常见默认权限
- 755 表示所有者可读写执行、组和其他用户可读可执行，是脚本和目录的常见权限
- **目录的 x 权限与文件的 x 权限语义不同**：文件的 x 表示可执行；目录的 x 决定能否进入或遍历该目录路径、能否访问目录内条目
- 让普通用户能读取但不能修改文件，设置为 644 即可
- 为什么目录默认 755、文件默认 644：见下方 umask——目录需要 x 才能被进入，文件默认不带 x 以防被误执行

### umask

- **机制**：umask 是"屏蔽位"，创建文件时从系统默认权限中减去 umask 屏蔽的位，得到最终权限
- 系统对文件的默认基数是 666、目录是 777；默认 umask 022 屏蔽"组和其他人的写位"，于是新文件 = 666 − 022 = 644，新目录 = 777 − 022 = 755
- 为什么文件不像目录那样默认带执行位：为防安全风险，新文件默认不授予执行权限，需要时手动 chmod +x
- umask 只作用于新建对象，不影响已存在文件的权限
- 常见默认：新建文件 644，新建目录 755

### 权限命令

- chmod 修改权限，chown 修改所有者和组
- ls 查看目录内容，stat 查看文件详细属性
- find 按条件查找文件，grep 在文本中搜索
- 权限不足报错 Permission denied 时，优先查运行用户及目标文件或目录权限
- 衔接：文件权限是"静态资源"管理；系统运行时的动态主体是进程——下一节讲进程、信号与服务管理。

## 2.6 进程与服务管理

> 本节解决：进程是什么、如何被治理（信号）、服务如何由 systemd 管理、故障如何查日志。

### 进程与线程

- **进程是资源分配的基本单位**，具有 PID、状态、父子关系和信号等属性
- 线程属于进程内部的执行单元，同一进程的线程共享地址空间，通信成本低
- 进程生命周期受会话和程序设计影响
- 父进程退出后，子进程是否继续运行取决于进程状态、会话和程序设计等具体情况
- 服务通常由进程实现，但普通进程属于系统服务
- 进程常见状态包括运行、睡眠、停止、僵尸
- **僵尸进程是已退出但仍占用进程表项的进程**，由父进程回收；若父进程不回收，僵尸持续占用 PID 资源，大量堆积会拖垮系统
- 为什么进程需要状态机：CPU 无法同时运行所有进程，内核通过状态调度（运行/睡眠/停止）实现"看似并发"；僵尸则是退出到回收之间的过渡态

### 进程查看与排查

- ps 查看当前进程快照，top/htop 动态查看进程资源占用
- 查看高 CPU 进程的合理步骤：确认进程 PID 和命令，查看相关日志，观察 CPU 占用是否持续，结合业务判断是否异常
- 排查后如需处理，对确认异常的进程终止，不盲目终止所有进程
- 为什么"先观察再处理"：CPU 高可能只是瞬时任务，误杀正常进程会造成业务中断，先确认持续性再动手

### 信号机制

- **解决什么问题**：内核与进程之间需要一种轻量事件通知，信号就是这种机制
- 信号用于通知进程发生某类事件，进程可对部分信号设置处理
- SIGTERM 请求进程可控终止，进程可捕获并做清理后退出
- SIGKILL 由内核强制终止进程，目标进程无法捕获或忽略
- 为什么 TERM 可捕获而 KILL 不可：TERM 是"礼貌请求"，把清理机会留给进程；KILL 由内核直接执行，用于 TERM 无效或进程失控时的兜底
- 不同信号的处理方式不同，SIGKILL 和 SIGTERM 的语义有明显区别

### systemd 与服务管理

- **解决什么问题**：早期 init 按顺序串行启动服务、又慢又难管依赖；systemd 支持并行启动与依赖管理，是主流 Linux 系统的服务管理器
- systemctl status 查看服务状态，enable 配置开机自启
- **enable 与 start 的区别**：enable 只是把服务加入开机启动清单（创建符号链接），不等于当前时刻服务已经运行；start 才是立即启动，二者不可互相替代
- start/stop 控制服务启停，disable 取消开机自启
- 服务修改配置后需要重新加载自身配置，具体是否支持 reload 取决于服务本身能力，必要时才用 restart
- 为什么优先 reload 而非 restart：reload 不中断服务、只在运行中重读配置；restart 会中断连接，仅当服务不支持 reload 或需重置状态时使用
- 服务配置修改后应使用 reload 或 restart 使配置生效

### 日志与定时任务

- journalctl 查看 systemd 日志，结合时间线定位故障
- crontab 配置定时任务，按分时日月周执行命令
- 故障排查应结合时间线、错误日志、权限、资源和配置逐层定位
- 故障记录保留时间、操作和结果，有助于复现问题、审计过程和重复试错
- 衔接：进程运行会持续消耗内存与磁盘——下一节讲存储管理。

## 2.7 存储管理

> 本节解决：从 CPU 到磁盘的存储层级如何运作、内存不足怎么办、磁盘如何组合与保护数据。

### 分层存储体系
```
寄存器（最近/最快/最小）
  → 缓存 Cache
    → 内存
      → 外存（最远/最慢/最大）
```

计算机存储按速度与容量分层组织：

- 寄存器最靠近 CPU 核心，容量最小、访问最快
- 缓存 Cache 利用**局部性**降低访存开销：程序倾向于访问近期访问过或相邻的数据，Cache 把高频数据放在 CPU 附近，命中率高则访存开销大幅下降
- 内存、外存依次速度递减、容量递增
- 实际访存效率受缓存命中率、内存延迟和访问模式共同影响
- 为什么需要分层而不是只用一块大内存：速度与容量/成本不可兼得，用快而小的寄存器/缓存承接高频访问、慢而大的外存承接海量数据，是性能与成本的最优组合

### swap

- **解决什么问题**：内存不足时若直接终止进程（OOM）损失太大，swap 提供缓冲
- swap 是磁盘上的交换分区或交换文件
- swap 在内存压力等情况下提供辅助的虚拟内存空间
- 内存不足时系统把部分不活跃页面换出到 swap，腾出物理内存给活跃进程，需要时再换回
- 为什么 swap 是"辅助"而非"主力"：磁盘远慢于内存，频繁换入换出会显著拖慢系统，swap 只能缓解短期压力，不能替代扩容内存

### 磁盘管理与空间排障

- UOS 磁盘管理器用于查看磁盘与分区信息，可进行分区、挂载及逻辑卷管理
- 磁盘、分区和文件系统相关管理属于磁盘管理器职责
- 根文件系统空间不足会影响日志、临时文件等写入，造成应用异常
- 定位角度：大文件或大目录、日志增长、临时文件、被删除但仍被进程打开的文件
- df 查看分区空间使用，du 统计目录占用
- **删除的文件若仍被进程打开，空间不会立即释放**：inode 仍被引用，需定位占用进程并关闭或重启它，空间才会释放
- 为什么 df 显示满但 du 统计很小：正是"被删除但仍打开"的文件占着空间，du 按目录看不到已删除文件，df 按分区统计才反映真实占用

### RAID（独立磁盘冗余阵列）与数据备份

- **RAID 解决什么问题**：单块磁盘损坏即丢失数据，RAID 把多块磁盘组合成逻辑卷，用冗余换取可靠性或性能
- RAID0 条带化提升性能但无冗余，RAID1 镜像提供冗余，RAID5 带奇偶校验兼顾性能与冗余
- 为什么 RAID5 能容错：用奇偶校验位记录冗余信息，单块盘损坏时可由其余盘结合校验重建
- 数据备份分全量、增量、差异三种，全量备份数据最完整
- 备份后需验证可恢复性，备份介质与生产环境隔离
- **RAID 与备份的关系**：RAID 只防硬件故障，不防误删、病毒或逻辑损坏；备份才是应对这些场景的兜底，二者互补不可替代
- 衔接：进程与文件都依赖网络提供服务与访问——下一节讲网络。

## 2.8 网络

> 本节解决：网络为何能通、域名如何解析、服务如何安全地对外暴露。

### 网络连通性

- **连通性依赖五要素**：子网、网关、路由、DNS 和监听地址，任一环出问题都会导致访问失败
- 同一局域网内可通信但访问其他网段失败，优先检查默认网关和路由
- **监听地址决定服务对外可见范围**：服务只监听 127.0.0.1 时仅本机可访问，其他主机无法直接访问；监听 0.0.0.0 表示所有接口
- 为什么 127.0.0.1 与 0.0.0.0 不同：127.0.0.1 是回环接口、只代表本机；0.0.0.0 绑定所有网卡，其他主机才能连入；排查"外部访问不了"先看监听地址
- 常用命令：ip 查看地址与路由，ss 查看端口监听，ping 测试连通，traceroute 追踪路径

### DNS 解析

- **解决什么问题**：人记域名、机器记 IP，DNS 把域名解析为 IP 地址
- 域名解析失败时访问网站报无法解析
- 本地 DNS 服务器配置在 /etc/resolv.conf
- 为什么排障先查 DNS：ping 通 IP 但打不开域名页面，往往是 DNS 解析失败而非网络不通，两者要区分

### 网络服务安全

- **原则：最小暴露面 + 强认证**。SSH 等远程服务暴露到不可信网络时，限制访问来源并使用强认证等措施
- 关闭不需要的网络服务可减少系统攻击面
- 远程服务应限制不必要的访问来源并采用可靠身份认证
- 防火墙工具 firewalld、ufw 控制访问规则
- **HTTPS 在 HTTP 之上叠加 TLS 加密**，证书用于验证服务器身份
- HTTPS 站点报证书错误，优先检查系统时间和证书链
- 为什么证书错误先查系统时间：证书有有效期，本机时间偏差过大时会被判定"已过期/未生效"，这是最常见的误报原因
- 衔接：系统就绪、资源可管理后，如何安装和更新软件——下一节讲软件包管理与生态适配。

## 2.9 软件包管理与生态适配

> 本节解决：软件如何安装、依赖冲突怎么排查、国产生态下程序为何可能跑不起来。

### 包管理机制

- **解决什么问题**：软件依赖其他库，手工安装易出错；包管理器统一解决下载、依赖、版本、卸载
- 软件包管理依赖软件源、包索引、依赖版本和目标架构
- 软件源定义了包的获取地址，包索引记录可用包信息
- 安装应用时按依赖关系解析并安装依赖包
- 为什么需要包索引：安装前先在本机索引里查"这个包有哪些依赖、当前源里有哪些版本"，避免装到一半才发现缺依赖

### 依赖问题处理

- 应用安装失败提示依赖版本冲突，先分析依赖关系和软件源一致性再解决冲突
- 安装失败提示依赖无法满足时，检查：依赖版本是否冲突、目标架构是否有对应包、软件源是否一致可用、包索引是否已更新
- 为什么四个检查项对应四类原因：版本冲突是包版本互斥、架构缺失是仓库未提供该 CPU 架构的包、源不可用是下载失败、索引未更新是本机缓存过期——排查需逐项排除
- 强制删除系统库等破坏性操作会损坏系统

### UOS 应用商店

- UOS 应用商店支持搜索应用、下载安装、更新以及卸载可卸载应用
- 应用商店的管理能力覆盖安装、更新、搜索、卸载
- 与命令行包管理互补：GUI 商店面向普通用户，命令行适合脚本化与批量管理
- UOS 25 全盘安装要求目标盘至少 64GB，空间不足时安装器可能无法完成最小化分区配置

### 生态适配

- **核心原理**：程序能否运行取决于"指令集 + 运行库 + ABI"三层是否匹配
- 新设备在系统中完全不可识别且硬件本身正常，优先确认对应驱动是否支持该设备
- 设备能被系统识别不等于全部功能和稳定性已完成兼容验证
- 硬件兼容需要同时考虑 CPU 架构、固件、驱动、操作系统、外设和应用
- **动态链接程序能否运行受共享库架构和 ABI 兼容性影响**：x86 程序在 ARM 机器上因指令集不同不能直接运行，需重新编译
- 应用启动报缺少共享库，属于运行时依赖适配不完整，可用 ldd 查看缺失库后补装对应架构的库
- 为什么"能识别"不等于"已兼容"：识别只说明驱动加载成功，功能、稳定性、性能仍需逐项验证（与第 5 章 ISA/ABI、兼容性层次对应）
- 衔接：以上是管理系统的原理与命令；实操任务要求真实采集系统信息——下一节给出命令清单。

## 2.10 系统信息采集命令

> 本节解决：实操任务如何用真实命令采集系统信息，不手工编造。

实操任务要求通过系统命令获取真实系统信息，不得手工编造，对应命令如下：

| 信息 | 命令 |
|---|---|
| 当前登录用户名 | whoami |
| 主机名 | hostname |
| CPU 架构 | uname -m |
| Linux 内核版本 | uname -r |
| 系统完整信息 | uname -a |
| 当前日期和时间 | date |
| 根分区磁盘使用情况 | df -h / |
| 当前内存使用情况 | free -h |
| 网络接口及 IPv4 地址 | ip addr |

- 系统信息采集类任务统一用命令获取，输出重定向写入文件，例如 uname -r > 文件名
- 网络接口信息中找状态为 UP 的接口及其 inet 行对应的 IPv4 地址
- 为什么必须用命令而非凭记忆填：实操按真实环境评分，命令输出即证据，编造数据无法通过核验

- 系统信息中可查看 CPU、内存、系统版本等硬件与系统信息
- UOS 应用商店用于安装和更新应用，与命令行包管理互补
